# Conversation Research Method Design

## 목적

- 공개 자료를 그대로 응답 규칙으로 승격하지 않는다.
- 실제 연인 메신저 대화에 가까운 흐름만 보조 근거로 삼는다.
- 자동자막 특유의 잘림, 독백, 시청자 대상 멘트를 규칙층으로 끌어올리지 않는다.

## 기존 방식의 문제

- `커플`, `부부`, `브이로그` 같은 검색어만으로도 독백형 영상이 많이 섞인다.
- 유튜브 자동 자막은 화자 분리가 약해서 문장 단위만 보면 맥락이 끊기기 쉽다.
- 짧은 조각도 카테고리 키워드만 맞으면 카탈로그에 들어갈 수 있었다.
- 원시 코퍼스 예시가 승인 후보 채굴 단계까지 바로 연결돼 과신 위험이 있었다.

## 새 원칙

### 1. 원천 선별

- 제목에 `커플`, `부부`, `신혼`, `장기연애`, `couple`, `relationship` 같은 관계 신호가 있어야 한다.
- 제목이나 검색 질의에 `Q&A`, `대화`, `토크`, `문답`, `conversation`, `talk` 같은 대화 신호가 있으면 우선한다.
- `육아`, `임신`, `출산`, `family`, `kids`, `baby` 중심 영상은 현재 목적에서 제외한다.

### 2. 자막 대화성 검사

- 시청자 대상 멘트 비율이 높으면 제외한다.
- 질문/응답형 문장 비율이 낮으면 제외한다.
- 관계 호칭, 상호지시, 짧은 반응 같은 대화 마커가 충분히 있어야 한다.
- 영상 단위 점수가 낮으면 문장 품질이 좋아 보여도 전체 소스를 버린다.

### 3. 문장 단위 정제

- 너무 짧은 조각, 잘린 어미, 반복 노이즈, 독백형 진행 멘트는 제외한다.
- 원시 코퍼스는 `보조 예시`로만 남기고, 카탈로그의 핵심 예시는 실제 런타임 로그와 승인 패턴이 우선한다.

### 4. 승인 후보 채굴

- 자동 승인 후보는 `approved_examples`, `runtime_examples`, `user_examples` 같은 신뢰층에서만 뽑는다.
- `corpus_examples`는 사람이 보는 참고층으로 두고 자동 승인 루프의 직접 입력으로 쓰지 않는다.

## 기대 효과

- 응답 규칙이 브이로그 독백체로 오염되는 위험이 줄어든다.
- 실제로 쓸 만한 패턴과 단순 참고 샘플의 경계가 분명해진다.
- 리서치 결과를 `규칙 생성 데이터`가 아니라 `보조 관찰 데이터`로 다루게 된다.

## 아직 남는 한계

- 자동 자막 기반이므로 1:1 메신저 대화만큼 정밀하지 않다.
- 화자 추정은 여전히 약하다.
- 따라서 공개 코퍼스는 계속 `룰 생성 주재료`가 아니라 `보조 검증 재료`로만 다뤄야 한다.
