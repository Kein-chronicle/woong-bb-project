# 아이디어 설계

이번 세션에서 내가 더 발전시키고 싶은 건 아래 2개다.

- 설계 A: `엑트 보상 드래프트`
- 설계 B: `태그 연구 과제`

둘을 같이 묶으면, `엑트 클리어로 선택지 층을 열고`, `태그 운용 성취로 그 층의 깊이를 연다`는 구조가 된다.

---

## 설계 A. 엑트 보상 드래프트

### 1. 시스템 흐름

1. 플레이어가 Act를 클리어한다.
2. 보상 화면에서 3개 후보를 본다.
3. 후보는 서로 다른 축에서 나온다.
4. 플레이어는 1개만 고른다.
5. 그 선택은 다음 런부터 적용된다.
6. 적용 방식은 즉시 수치 버프가 아니라 `후보군 개방`, `가중치 상승`, `새 노드 등장`이다.

내가 여기서 지키고 싶은 건 단 하나다. 보상은 승리를 주면 안 되고, `다음 런에서 해볼 만한 방향`을 줘야 한다.

### 2. 데이터 구조

```json
{
  "actRewardPools": [
    {
      "act": 1,
      "choices": [
        {
          "id": "unlock_curse_research",
          "type": "tag_unlock",
          "tag": "curse",
          "effect": "enable_curse_research_tasks"
        },
        {
          "id": "route_pressure_trial",
          "type": "route_unlock",
          "routeNode": "pressure_trial",
          "effect": "add_route_node_to_map_pool"
        },
        {
          "id": "wave_pool_bias",
          "type": "offer_bias",
          "group": "wave",
          "effect": "increase_wave_weapon_offer_weight"
        }
      ]
    }
  ]
}
```

### 3. 플레이어 경험

- 초반에는 `아직 못 여는 문`이 보여서 게임이 얇지 않고, 앞으로 열릴 층이 있다는 기대가 생긴다.
- Act 1 클리어 직후엔 `내가 어떤 문을 먼저 열지`가 다음 런의 이유가 된다.
- 여러 엑트를 통과할수록 플레이어는 자기 저장파일이 `범용 스펙업 계정`이 아니라 `내가 고른 해금 이력`으로 느껴진다.

### 4. 웨일서바이버에 특히 맞는 이유

- 승인 무기 20종만 있어도 `어떤 태그/무기군을 더 잘 만나게 할지` 설계 가능하다.
- 항해 노드가 이미 게임의 별도 레이어라서, 전투 외 보상축을 자연스럽게 붙일 수 있다.
- 최근 방향인 `선택지 확장형 메타 성장`과 충돌하지 않는다.

---

## 설계 B. 태그 연구 과제

### 1. 시스템 흐름

1. 플레이어는 먼저 설계 A에서 `해당 태그 연구권`을 연다.
2. 그 다음 런부터 그 태그에 대한 연구 과제가 표시된다.
3. 과제는 런 안 성취로 완료한다.
4. 완료하면 상위 단계 태그 관련 카드, 이벤트, 보상 후보군이 영구 개방된다.
5. 즉 `문을 여는 권리`와 `문 안으로 들어가는 실력`을 분리한다.

이 구조가 좋은 이유는, 메타에서 다 열어주지 않기 때문이다. 플레이어는 런 안에서 실제로 그 태그를 운용해봐야 한다.

### 2. 데이터 구조

```json
{
  "tagResearch": [
    {
      "tag": "curse",
      "unlockRequirement": "act1_reward_selected",
      "tasks": [
        {
          "id": "curse_trial_01",
          "goal": "defeat_elites_with_curse_tier_3",
          "count": 10,
          "reward": "enable_curse_tier_3_sources"
        },
        {
          "id": "curse_trial_02",
          "goal": "clear_boss_with_curse_tier_4",
          "count": 3,
          "reward": "enable_curse_tier_4_sources"
        }
      ]
    }
  ]
}
```

### 3. 플레이어 경험

- 태그 3~4단계가 단순 설명문이 아니라 `내가 실제로 연구해서 연 체계`처럼 느껴진다.
- 과제가 있으면 런 목표가 생긴다. `이번 판은 저주 4단계 보스 처치를 노린다` 같은 식이다.
- 실패해도 `아예 허무한 실패`가 아니라, 다음 목표를 더 선명하게 본 상태로 돌아오게 된다.

### 4. 웨일서바이버에 특히 맞는 이유

- 최근 대화에서 이미 태그 1~4단계가 중요한 전투 언어로 자리 잡아 있다.
- 그래서 태그를 메타 성장의 문으로 다시 쓰면 시스템이 늘어나는 게 아니라 기존 축이 더 선명해진다.
- `저주 1~2는 지금도 보이고, 3~4는 연구 후 제대로 노릴 수 있다`는 구조가 현재 프로젝트 고민과 직접 맞닿는다.

---

## 두 설계를 같이 썼을 때의 효과

- 설계 A만 있으면 보상은 있는데 목표가 약해질 수 있다.
- 설계 B만 있으면 과제는 있는데 왜 그 과제가 열렸는지 계층감이 약하다.
- 둘을 합치면 `엑트 클리어로 연구 분야를 열고 -> 런에서 실전 연구를 끝내고 -> 다음 런의 태그 깊이가 열린다`가 된다.

내 기준에선 이 조합이 지금 웨일서바이버가 가진 `전투 + 항해 + 태그 + 메타`를 가장 적은 추가 시스템으로 묶는다.
