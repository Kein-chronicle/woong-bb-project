# 아이디어 설계

이번 세션에서는 아래 2개를 묶어서 본다.

- 아이디어 A: `엑트 열쇠 보상`
- 아이디어 B: `태그 공명 면허`

이 둘을 합치면 `엑트 클리어 -> 성장 오픈 -> 다음 엑트 돌파`가 가장 또렷하게 선다.

---

## 1. 시스템 흐름

### 기본 루프

1. 플레이어가 Act N을 클리어한다
2. `심해 열쇠` 1개를 얻는다
3. 보상 화면에서 3개 후보 중 1개를 고른다
4. 그 선택은 다음 런부터 영구 적용된다
5. 다음 Act는 방금 연 선택지가 있으면 훨씬 수월하지만, 그래도 런 안에서 다시 빌드를 맞춰야 한다

### 보상 후보의 3개 슬롯

- `태그 면허`
  - 예: `저주 면허 II` 해금
  - 효과: 이제 런 안에서 저주 3~4단계 관련 카드/이벤트가 후보군에 등장 가능
- `전투 선택지`
  - 예: `공용 무기 후보 +1`, `특정 태그 카드군 개방`
  - 효과: 빌드 완성 속도와 방향성을 넓힘
- `항해 선택지`
  - 예: `새 노드 유형 등장`, `노드 보상군 확장`
  - 효과: 런 중간 선택의 성격을 바꿈

### 왜 이 구조가 맞는가

- 엑트 보상이 곧바로 `다음 엑트 공략 도구`가 됨
- 하지만 보상이 곧 승리를 보장하지는 않음
- 즉 메타 성장과 런 내부 성장의 역할이 분리됨

---

## 2. 데이터 구조

### 보상 정의 예시

```json
{
  "actRewards": [
    {
      "id": "act1_clear_reward_pool",
      "act": 1,
      "choices": [
        {
          "id": "license_curse_2",
          "type": "tag_license",
          "tag": "curse",
          "unlockTier": 2,
          "effect": "enable_curse_tier_3_4_sources"
        },
        {
          "id": "weapon_pool_wave_plus",
          "type": "weapon_pool_unlock",
          "group": "wave",
          "effect": "add_wave_weapon_choice_weight"
        },
        {
          "id": "route_pressure_node",
          "type": "route_unlock",
          "node": "pressure_trial",
          "effect": "enable_pressure_route_rewards"
        }
      ]
    }
  ]
}
```

### 핵심 규칙

- `tag_license`는 태그 상한을 바로 올리는 게 아니라, 그 상한에 닿는 수단을 후보군에 추가함
- `weapon_pool_unlock`은 고정 지급이 아니라 선택 풀 가중치 또는 후보군 확장 방식으로 처리
- `route_unlock`은 항해 단계에서만 의미가 생기므로, 전투 보상과는 다른 리듬을 줌

---

## 3. 플레이어 경험

### 초반

- 시작 시점에는 태그 1~2단계 위주라 빌드가 조금 덜 열린 느낌
- 대신 무엇을 먼저 열지 고르는 재미가 생김

### 중반

- Act 1 클리어 후 `내가 연 문` 때문에 다음 런이 달라졌다는 감각이 바로 옴
- 예를 들어 저주 면허를 열면, 이제 저주 3~4단계를 진짜 노릴 이유가 생김

### 후반

- 여러 엑트에서 연 문들이 겹치며 후반부에 빌드 폭발 구간이 생김
- 이때 해방감은 크지만, 그 폭발이 `엑트마다 내가 고른 문`의 누적으로 느껴짐

---

## 4. 웨일서바이버 기준으로 특히 좋은 점

- 이미 있는 태그 시스템을 메타 성장의 축으로 재활용할 수 있음
- 승인된 무기 20종만으로도 `어떤 태그/무기군을 다음 런에 더 잘 열지` 설계가 가능함
- 최근 메모의 `밖에서는 선택지 확장, 안에서는 빌드 완성` 원칙과 정확히 맞물림

---

## 5. 지금 단계에서 주의할 점

- 면허가 곧바로 수치 버프가 되면 안 됨
- 각 엑트 보상 후보 3개는 `서로 다른 문제를 푸는 선택지`여야 함
- 다음 엑트가 특정 선택 없이는 막히면 안 되고, `있으면 납득되게 편해지는 정도`로 맞추는 게 좋음
